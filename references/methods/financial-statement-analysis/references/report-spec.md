# HTML 财务报告输出规范

## 1. 视觉基线（浅底研报风）

```css
:root{
  --bg:#f5f6f8; --card:#ffffff; --line:#e4e7eb;
  --text:#1a1d21; --sub:#5b636b; --mute:#7b848d;
  --brand:#1f4e79; --brand2:#2e6da4; --brandbg:#eaf1f8;
  --green:#1f7a4d;   /* 优秀 / 通过 */
  --amber:#b8860b;   /* 关注 */
  --red:#c0392b;     /* 预警 / 风险 */
  --purple:#6b4c9a;  /* 辅助强调 */
}
```

- 背景浅灰、卡片纯白、细边框，圆角 6—10px，阴影 `0 1px 3px rgba(16,24,40,.06)`
- 字体：`-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`
- 正文 13.5—14px / 行高 1.75；标题 15—20px；数字用等宽或 `font-variant-numeric: tabular-nums`
- 正文宽度 ≤1180px，图表宽 100%、高 320—420px
- 打印友好：加 `@media print` 隐藏交互控件

## 2. 组件清单

| 组件 | 用途 |
|---|---|
| `.hero` | 报告标题区：公司名 + 代码 + 数据截止日 + 一句话结论 |
| `.kpi` / `.kpi-grid` | 关键数字卡（大数字 + 标签 + 同比） |
| `.card` | 通用白卡，可加 `border-left:4px solid` 做状态色 |
| `.grid2` / `.grid3` | 卡片栅格 |
| `.tbl` | 数据表格：首列指标、次列数值、标准、判定、说明 |
| `.tag` / `.b-ok` / `.b-wt` / `.b-bad` | 判定标签（优秀/关注/预警） |
| `.cmp` | 勾稽闭环：横向节点流转图（净利润 → 调整 → 现金流 → 验证） |
| `.note` | 提示框（蓝底） |
| `.src` | 数据来源与口径说明（小字灰） |
| `.quote` | 中心论点 / 塔尖结论（左侧粗边 + 大字号） |

**体检表必含四列**：指标 → 数值 → 健康标准 → 判定 + 说明。判定用彩色标签。

## 3. 图表规范（ECharts 5）

CDN：`<script src="https://cdn.jsdelivr.net/npm/echarts@5/dist/echarts.min.js"></script>`

配色决策：
- **股价/涨跌幅**：中国惯例 **涨=红 `#c0392b`、跌=绿 `#1f7a4d`**
- **健康度判定**：优秀=绿、关注=橙、预警=红（体检语义，与涨跌无关）
- 主数据系列用 `--brand` 蓝；对比同业用灰 `#8b949e` 与紫 `#6b4c9a`
- 柱状图一律 `barWidth:'24%'`（系列多时），line 图 `lineStyle:{width:3}, symbolSize:7`

必遵守的技术约束（踩过的坑）：
1. **序列长度必须与 `xAxis.data` 类目数严格一致**，否则整体错位。含 `null` 的数组再 `concat` 前导 `null` 会多出元素——直接用完整长度数组填 `null`。
2. 每个图表容器 `id` 唯一，`echarts.init(document.getElementById('chartN'))`。
3. 图表容器必须有明确 `height`（px），否则高度为 0。
4. 数据量级差异大时用双 y 轴，并给次轴命名。
5. 负值柱（投资/筹资流出）直接给负数值，不要取绝对值。

## 4. 章节结构

### 4.1 单项分析（如"利润表四步分析"）
```
标题/摘要 → 四步逐一（每步：结论卡 + 图表 + 数据表）→ 关键判断 3 条 → 跟踪指标 → 免责声明
```

### 4.2 财务体检总报告
```
一、企业体检表（八大模块 50+ 项）
二、体检评分与画像（雷达图 + 判定分布）
三—五、三表深度
六、三表勾稽
七、同业对照
八、风险清单 + 跟踪阈值
九、投资结论
```

### 4.3 管理决策版（叠加四框架）
按 `references/management-frameworks.md` 第 5 节的组装顺序。

## 5. 写作要求

- 每个结论**必须挂数据**：「核心利润占营业利润 96.8%」而非「核心利润占比高」
- 双口径并列（如核心利润 96.8% / 剥离财务费用后 84.9%），并在 `.src` 说明差异
- 关键判断控制在 3 条，每条一个小标题 + 论据 + 数字
- 口径修正要显著标出（如"与已交付报告有出入，以本份为准"）
- 结尾固定免责声明：
  > 以上内容基于公开数据和量化分析，仅供参考，不构成投资建议。市场有风险，投资需谨慎。任何投资决策应结合个人风险承受能力、资金状况和投资目标独立判断，必要时咨询持牌专业机构。过往表现不预示未来收益。

## 6. 生成与交付流程

1. **数据先行**：数据全部取齐、交叉核对后再写报告，不要边写边补数。
2. **分段写入**：先 `Write` 主体骨架并留占位注释（`<!--PART2-->`），再用 `Edit` 逐段替换。避免一次写超长文件导致截断。
3. **收尾检查**：分段写入最容易产生重复的 `</body></html>`——**必须 grep 确认只出现一次且在末尾**。
4. **校验**：`python scripts/check_report.py 报告.html`，必须给出 `[OK] 内联 JS 语法` 且 0 个 `[ERR]`。
5. **交付**：用 `present_files` 打开文件，并在回复中给出核心结论表格（不重复罗列全部数据）。

## 7. 常见错误清单

| 错误 | 后果 | 预防 |
|---|---|---|
| ECharts series 长度 ≠ 类目数 | 图形整体错位 | 写完逐个数一遍；`check_report.py` 会列出长度分布 |
| 分段写入产生重复 `</body></html>` | 页面尾部出现重复片段 | grep 计数 |
| 容器 id 重复 | 第二个图表不渲染 | `check_report.py` 自动检查 |
| 用列索引取 westock 数据 | 全部科目错位 | 一律用表头名称映射 |
| 单期数据下结论 | 判定失真 | 强制十年序列 |
| 直接引用 westock 的毛利率字段 | 得到 0 | 自算 |
| 印象计数（如"6 年满足某组合"） | 数字错误 | 逐年核对 |
