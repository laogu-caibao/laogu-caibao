# 数据源指南

> **本 Skill 不绑定任何数据源。** 开始前必须先问用户手上有什么，再决定取数方式。
> 没有数据时宁可说"缺这个数"，也不要估算、不要用模型记忆里的数字编。

## 一、数据源优先级

**按「能力」选，不要按工具名记。** 右列只是本机已验证的实例，
换环境时只需替换实例列，左列的能力需求与取数逻辑不变。

| 序 | 需要的能力 | 拿什么 | 本机实例 | 前置条件 |
|:--:|---|---|---|---|
| **1** | 实时行情接口 | 行情、市值、PE/PB/ROE/最新一期现金流 | 通达信 MCP | 开箱即用 |
| **2** | **公告检索 + 正文解析** | **财报原文与全部附注** | alphapai-lite-mcp | 无需文件 |
| 3 | 本地金融数据库 | 历史三表、财务摘要、同行批量对比 | akshare | 需 `pip install` |
| 4 | 财报 PDF | 原文、附注、分部数据 | 用户文件 / 官网下载 | 需文件 |
| 5 | 用户直接粘贴 | 已整理好的指标表格 | — | 用户提供 |
| 6 | 联网搜索 | 兜底、交叉验证（行情/市值/研报引用） | WebSearch | 需核时效 |

> ⚠️ **任何一项都不可用就直接跳过，不要卡在重试。** 实测过通达信会话失效
> （`No valid session ID provided`）、第三方接口随网站改版失效——连续两次失败即换下一条。
>
> ⚠️ **行情接口只给最新一期快照，看不到附注，也给不了三年历史。**
> 需要多年数据或附注时，直接用第 2 / 3 / 4 项，别在行情接口上浪费调用。
>
> 💡 **第 1 项与第 2 项互补**：行情给"市场怎么看"，原文给"公司实际怎样"。
> 理想组合是两者都用，只用其一都会有盲区。

## 二、通达信 MCP（首选）

**为什么排第一**：一次调用同时返回行情与财务指标，无需拼装，对个人用户零配置成本。

> 若你的环境**没有这个连接器**，直接跳到第三节（本地数据库）或第四节（财报原文）。
> 行情数据也可以靠联网搜索兜底，不是非它不可。

```
tdx_quotes(code="600519", setcode="1", hasCwInfo="1", hasExtInfo="1")
```

| 参数 | 取值 |
|---|---|
| `code` | 纯数字股票代码 |
| `setcode` | `1`=沪市（6/68 开头）· `0`=深市（00/30 开头）· `2`=北交所 · `31`=港股 |
| `hasCwInfo` | `"1"` 返回 PE(TTM)/PB/ROE/总市值/每股收益/经营现金流 |
| `hasExtInfo` | `"1"` 返回昨收/今开/最高/最低/量比/换手率 |

**能拿到什么**：现价、涨跌幅、总市值、PE(TTM)、PB、ROE、每股收益、每股净资产、
资产负债率、营业收入、营业成本、净利润、经营现金流、应收账款、存货、股东户数。

**已知限制**：
- 只返回**最新一期**财务快照，历史多年数据需换其他源
- 北交所标的（setcode=2）可能返回空数据，需换源核实
- 拿到的是汇总口径，附注级明细（如减值构成、分部数据）需查财报原文

> ⚠️ **空数据红线**：接口返回空时，必须如实告诉用户"该标的无数据"，**禁止编造任何数字**。

## 三、本地金融数据库（需安装）

拿**历史三年数据**的主力。若装不了或不想装，可用财报原文（第四节）逐年替代，
只是手工成本高一些。

```bash
pip install akshare
```

| 用途 | 接口 |
|---|---|
| 三表原始科目（含全部明细） | `stock_financial_report_sina(stock="600519", symbol="利润表")` |
| 财务摘要（周转率、ROE、毛利率等 80 项） | `stock_financial_abstract(symbol="600519")` |
| 业绩报表/预告/快报 | `stock_yjbb_em(date="20260630")` |

**symbol 可选值**：`利润表` · `资产负债表` · `现金流量表`

### 网络环境注意

若你的环境配置了 HTTP 代理，拉取东财/新浪接口时可能被拦截。此时需绕过代理：

```bash
env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy NO_PROXY='*' no_proxy='*' python script.py
```

**判定方法**：直接跑一次，若报 `RemoteDisconnected` 或连接超时，就加上上述前缀重试。
不要一上来就加——多数环境不需要。

**个别接口可能失效**：某些第三方数据接口会随网站改版而失效。
遇到报错时换等价接口，或降级到通达信/财报原文，不要卡在重试里。

## 四、财报原文与附注

> ⚠️ **附注只能从财报原文获取。** 结构化数据接口（AKShare 摘要、通达信 CwInfo）
> **都看不到附注**——它们返回的是加工后的汇总口径。
>
> **本节不绑定任何特定工具。** 凡能提供「按公司+报告期检索公告」与
> 「返回公告正文/解析文本」两类能力的连接器或接口都可用。
> 下文举例只是已验证过的实例，换工具照样适用。

### 4.0 先判断：这一步真的需要原文吗？

取原文成本高（解析慢、文件大、占上下文）。**先按目标分类，能省则省**：

| 要查的东西 | 必须原文？ | 更快的替代 |
|---|:--:|---|
| 分产品/分地区收入与毛利率 | ❌ | AKShare `stock_zygc_em`（直接给分部构成） |
| 三表科目余额 | ❌ | `stock_financial_report_sina` |
| 周转率 / ROE / 毛利率等比率 | ❌ | `stock_financial_abstract` |
| **货币资金受限金额** | ✅ | — |
| **应收账款账龄结构** | ✅ | — |
| **存货构成（原材料/在产品/库存商品）** | ✅ | — |
| **其他应收款的款项性质** | ✅ | — |
| **现金流量表补充资料** | ✅ | — |
| **关联方交易、或有事项、日后事项** | ✅ | — |
| **商誉标的与减值测试假设** | ✅ | — |

> **判据**：凡是"**三表里只有一个总数、看不见内部结构**"的科目，都必须查原文。
> 唐朝说的"必须披露却不想让你明白的东西"，指的就是这批。

### 4.1 获取路径（任选一条走得通的，不必按顺序，可组合）

#### 路径 A：公告检索连接器（推荐）

适用于：环境里有能检索公告 + 返回正文的连接器。

```
① 按公司名检索定期报告 → 拿到文档 ID
② 用文档 ID 下载正文（优先 markdown / 已解析格式）
```

**已验证实例的排查笔记**（换工具时可作为思路，不必照抄参数）：

| 现象 | 原因 | 解法 |
|---|---|---|
| 用股票代码检索返回"未找到" | 代码后缀格式不匹配（如 `"000811.SZ"`） | 改用**公司名称**检索 |
| 关键词搜不到 | 标题用词差异：`"半年度报告"` 无结果 | 换更短的词根：**`"半年度"`**；类型筛选参数可能无效 |
| 返回体过大被截断 | 半年报约 20 万+ 字符 | 见 4.2 大文件处理 |

**顺带可一并检索**：`非经营性资金占用及其他关联资金往来情况汇总表`
——核查关联方占款的现成材料，与"其他应收款"交叉验证。
这类**专项公告文件小、针对性强**，往往比翻整份年报更快。

#### 路径 B：财报 PDF + 解析脚本

适用于：用户手上有 PDF，或从官网下载了 PDF。

```bash
python3 scripts/parse_report.py <pdf> --keyword "关键词1" "关键词2" -o notes.txt
```

#### 路径 C：披露平台直接下载

适用于：没有连接器、也没有现成 PDF。

巨潮资讯网、上交所、深交所官网均提供免费 PDF。
先用联网搜索定位该期报告的文件链接，下载后走路径 B。

#### 路径 D：结构化数据兜底（拿不到原文时）

若以上都走不通：

1. 用 AKShare 能拿到的部分先做（三表、摘要、分部构成）
2. 在报告「数据缺口」章节**逐项列明哪些附注没查到**
3. 在结论里**下调置信度**（措辞见 4.4）

### 4.2 大文件处理技巧

定期报告原文通常 20–40 万字符，必然超上下文。**不要试图整篇读**。

```bash
# ① 先复制到工作目录（某些临时目录 Read 工具无权访问，会 Permission denied）
cp <原始路径> /tmp/report.txt

# ② 用关键词定位行号，而不是顺序读
grep -n "现金流量表补充资料" /tmp/report.txt
grep -n "账龄\|受限\|或有事项" /tmp/report.txt

# ③ 定位后只切取需要的段落
sed -n '1776,1840p' /tmp/report.txt

# ④ HTML 表格先剥标签再读
sed 's/<[^>]*>/|/g' | tr -s '|'
```

**按 `@references/notes-checklist.md` 的顺序逐项定位**，不要通读。

### 4.3 关键词策略（搜不到时的递进尝试）

| 目标 | 首选词 | 退化词 |
|---|---|---|
| 半年报正文 | `半年度` | `中报`、`报告`（配合类型筛选） |
| 年报正文 | `年度` | `年度报告摘要`（信息少但可用） |
| 现金流调节表 | `现金流量表补充资料` | `将净利润调节为经营活动现金流量` |
| 账龄 | `账龄` | `1年以内` |
| 受限资产 | `受限` | `所有权或使用权受到限制` |
| 关联方 | `关联方` | `关联交易`、`资金往来` |

> 一个词搜不到就换，**不要反复重试同一个词**。
> 也可直接检索该公司的专项公告（如"非经营性资金占用汇总表"），
> 文件小、命中率高。

### 4.4 拿不到原文时的标准措辞

直接放进报告的数据缺口章节：

```markdown
**数据缺口**：本期未获取财报原文附注，以下项目无法验证——
货币资金受限金额、应收账款账龄结构、存货构成、其他应收款性质、
现金流量表补充资料、关联交易、或有事项。

上述缺口使以下判定**置信度下调**：
· 「存贷双高」无法确认货币资金是否受限 → 判定仅基于账面数
· 「应收质量」仅能看总额与周转天数，看不到账龄 → 无法识别长账龄风险
· 「现金流背离原因」无法拆解到存货/应收/应付各项 → 只能作定性推断

建议在拿到 {YYYY} 年半年报原文后复核上述三项。
```

### 4.5 用解析脚本时的关键词集

走路径 B/C 时，建议一次性抽取（覆盖 `@references/notes-checklist.md` 全部必查项）：

```bash
python3 scripts/parse_report.py report.pdf --keyword \
  "会计政策" "会计估计" "货币资金" "应收账款" "存货" "其他应收款" \
  "长期股权投资" "在建工程" "商誉" "短期借款" "营业收入" "研发费用" \
  "投资收益" "其他收益" "营业外支出" "减值" "现金流量表补充资料" \
  "关联方" "或有事项" "日后事项" "分部" -o notes.txt
```

**时间有限时的最小集**——至少取这四项：

| 目标 | 为什么必须有 |
|---|---|
| `现金流量表补充资料` | ⭐ 全份财报信息密度最高，解释净利润与经营现金流的差额 |
| 应收账款账龄 | 决定回款质量，是现金流分析的证据链 |
| 其他应收款性质 | 唐朝称"垃圾筐"，关联方占款常藏于此 |
| 分部数据 | 混合体拆算的唯一来源，没有它就无法分部估值 |

> 走路径 A（连接器已返回全文）时不必再跑脚本——
> 直接用 4.2 的 grep/sed 在全文里定位，最小集同样适用。

**最适合挖的东西**：附注、分部报告、减值明细、诉讼与担保、关联交易——
这些是财报里"必须披露但不太想让你看见"的部分，唐朝最看重的就是这里。

## 五、通用取数纪律

1. **先问再取**：开场确认用户有哪些源，不要默认某一个
2. **多源交叉**：关键数字（净利润、经营现金流）尽量两个来源对上再写进结论
3. **标注来源**：报告末尾列出每个数据项的出处
4. **缺口单列**：拿不到的数据写进「数据缺口」章节，**不能进结论**
5. **不编造**：这是财报分析的底线——一个编造的数字会让整份分析失效

## 六、最小数据需求

跑完八步法至少需要：

- [ ] 最近 **3 个完整年度** + 最新一期的三表数据（唐朝：至少 3 年，避免单年异常值）
- [ ] 同行业 **2–4 家**公司的可比指标
- [ ] 最新一期的市值/PE/PB（用于判断市场定价）

缺任何一项，先告诉用户缺什么、影响哪一步，再决定是继续还是停。
