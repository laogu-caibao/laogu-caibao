# 底稿规范（schema: cbfx.ledger/0.1）

底稿是分析层**唯一**的数据入口。分析、估值、写作里出现的每个数字，都必须能在底稿里找到对应单元格；底稿里没有的数，不许出现在报告里。

## 1. 产出目录

```
out/<代码>/<报告期>/          # 季报快检；年报深检为 out/<代码>/<报告期>-deep/
├── 底稿.json          # 本规范描述的结构，跨 agent 一致的唯一事实来源
├── 数据核对报告.md     # 人看的核对摘要（覆盖率、关键科目三源对照、问题清单）
├── 分析.json          # analyze.py 产出（schema cbfx.analysis/0.1）：archetype / changes / metrics（每项含 inputs、阈值、verdict）/ red_flags / valuation / headline
├── 快检报告.md 或 深检报告.md
├── filings/           # 下载的公告原文 PDF（文件名含公告 ID）
└── raw/               # 各来源原始返回：eastmoney.json、sina.json、pdf.json
```

`out/<代码>/分型.json`：最近一次深检的分型结果，快检沿用。

## 2. 顶层字段

| 字段 | 含义 |
|---|---|
| `schema` | 固定 `cbfx.ledger/0.1`；结构变动必须升版本号 |
| `meta` | 代码、名称、市场、公司模板（general/bank/insurance/securities）、目标报告期、报告类型（Q1/H1/Q3/FY）、模式（quick/deep）、生成时间、工具版本、各数据源状态 |
| `filings` | 用到的公告原文：标题、披露日、巨潮 URL、本地文件、解析出的科目数、审计意见、其他版本（更正/修订） |
| `periods` | 本次覆盖的报告期列表（快检 16 季；深检 24 季 + 近 10 个年度） |
| `fields` | 逐科目、逐报告期的核对单元格（见 §3） |
| `derived` | 单季差分、TTM、有息负债（近似口径），只由 `fields` 中 `usable=true` 的值计算 |
| `audit` | 审计意见（原文 / 新浪） |
| `quote` | 行情快照（价格、市值、PE/PB），注明来源与时间 |
| `coverage_target` | 目标期各状态的科目数 |
| `issues` | 问题清单：`level`（error/warn/info）、`field`、`period`、`msg` |
| `reconciliations` | 勾稽核对：同比基数＝原文比较列、期初＝原文期初列、期末现金≤货币资金（金融类 na）、未分配利润滚动；每项 `name/label/period/status(pass/warn/fail/na)/note`，warn/fail 同时写入 issues |

快检（季报/半年报）同时读取**上一份年报原文**（门禁要求），因此 `filings` 通常有两份。
`derived.sq_verified[字段][期间]="原文本报告期"` 表示该单季数已被原文本报告期单季列验证。

## 3. 单元格（`fields.<key>.values.<period>`）

```json
{"value": 26044249000.0, "status": "一致", "chosen_from": "pdf",
 "sources": {"pdf": 26044249000.0, "eastmoney": 26044249000.0, "sina": 26044249000.0},
 "usable": true, "max_rel_diff": 0.0, "pdf_page": 98}
```

- 金额一律**元**；流量科目（利润表、现金流量表）是**年初至报告期末累计**，单季看 `derived.single_quarter`。
- `chosen_from` 取值优先级：`pdf`（本期报告原文）> `pdf_comparative`（本期报告里的上年比较数）> `eastmoney` > `sina`。
- `pdf_page` 是 PDF 物理页码（从 1 起），写报告时引用“原文第 N 页”。

## 4. 状态含义（硬规则）

| 状态 | 判定 | 可否使用 |
|---|---|---|
| 一致 | 所有来源最大相对差 ≤ 0.1% | 可用 |
| 偏差 | 0.1% < 差 ≤ 1% | 可用，报告中注明“来源间小幅差异” |
| 冲突 | 差 > 1% | **不可用**，进问题清单（error）；须人工查原文后再用 |
| 追溯调整 | 本期报告中的比较期数 ≠ 接口存的当年原始数 | 可用（按调整后口径做同比），必须在报告中说明 |
| 原文自洽 | 只有原文（财报当日接口未更新），但报表数与原文“主要会计数据”表一致 | 可用；接口更新后重跑即可升级为“一致” |
| 单一来源 | 只有一个来源有值 | 可用，置信度低；关键结论不能只靠它 |
| 未获取 | 没有任何来源 | 不可用；报告写“未获取”，**不得估算填补** |

## 5. 分析层使用规则

1. 只读 `usable=true` 的值；`冲突` 的科目不得进入任何结论。
2. 有 `error` 级问题时，报告首屏必须写明“数据存在冲突项：……”，且不得给出“通过/健康”之类的总评。
3. 引用口径：同比用 `pdf_comparative`（已追溯调整）口径；单季用 `derived.single_quarter`；年化用 `derived.ttm`。
4. 比率的分子分母必须同口径：ROE 用**归母净利润 / 归母权益**（`np_parent` / `eq_parent`），不得用含少数股东的总权益。
5. `derived.interest_bearing_debt` 是近似口径（含一年内到期非流动负债全额），年报深检应用附注拆分校正后再下“偿债风险”结论。
6. `meta.company_type` 不是 `general` 时（银行/保险/券商），通用字段只覆盖共有科目，分析层必须走 `规则手册.md` 的金融适配口径，不得套用毛利率、存货周转、净现比等工商业指标。
