# 财报专用报告规范

本文件规定复杂报告的学术排版和视觉边界。报告数据结构与单命令构建方式见
[report-contract.md](report-contract.md)。不要调用系统通用 HTML Report Skill，
不要读取模板、样式、schema、渲染器或校验器源码，也不要让模型另写完整 HTML。

## 1. 视觉与版面

- 使用白底、深灰正文和单一深蓝强调色；仅用克制的红、绿、棕表达风险或方向。
- 禁止渐变、霓虹、阴影、动画、玻璃拟态、营销卡片和无信息价值的装饰。
- 使用固定 A4 纸张和稳定的单列阅读流。只有两段长度接近、且不含表格或图表的短叙述章节可成对双列；长正文、表格、图表、风险和证据索引独占整行。
- 中文正文优先宋体体系，标题优先黑体体系，英文与数字优先 Times New Roman。
- 正文字号不低于 10.5pt，图表和表格辅助文字不低于 6.5pt。
- 段落两端对齐，连续正文首行缩进 2 字；结论、题注、表格单元格不缩进。
- 控制孤行、寡行和跨页断裂；图形与题注尽量同页，长表格只在完整行之间分页并重复表头，不得为保持整表同页制造大片空白。

## 2. Header 与公司标识

Header 只包含：

1. 公司正式名称；
2. 证券代码与市场；
3. 公司 Logo 或正式字标；
4. 报告标题与一句话核心判断；
5. 报告期、披露日期、会计口径和数据截止日四项元数据。

不要在 Header 重复展示报告类型、报告期、标题、字幕和“核心判断”标签。报告类型应自然写入主标题；一句话判断直接作为标题下导语，不再另设小标题。

优先使用财报、公司官网或官方媒体资料中已获得的 Logo。把 PNG、JPEG、WebP 或 SVG 保存到本地，并在报告数据的 `company.logo_path` 中填写相对 JSON 文件的路径；渲染器会内嵌图片，最终 HTML 不依赖远程资源。

美团（03690）由渲染器自动使用 `assets/company-logos/meituan.png`，无需在运行时获取。其他公司如果任务材料中没有易于取得的 Logo，不要单独发起多轮搜索；填写 `company.short_name` 作为正式字标回退。不得使用第三方新闻站、Logo 聚合站或不明来源图标。

## 3. 学术文本规范

- 区分公司披露、分析计算和分析推断；推断使用“可能”“表明”“需验证”等限定语。
- 每段只表达一个核心判断，并按“事实—比较—原因—含义”组织。
- 首次出现的专业缩写给出全称；币种、单位、合并范围和会计准则保持一致。
- 同比写为“同比”，环比写为“环比”；利润率变化使用 `bps` 或“个百分点”，不要与百分比增速混用。
- 不制造虚假精度；估算值、未披露、未获取和口径不完全可比必须显式标记。
- 结论附近引用来源编号，来源编号链接到文末证据索引。

## 4. 学术表格规范

- 财务数据表使用严格三线表：只保留顶线、表头分隔线、底线；正文行之间不画灰线，不使用竖线、彩色底纹或密集网格。
- 每张表都必须有位于表格上方的连续编号与表题，例如“表 3　分业务收入与利润率”。
- 每张业务数据表填写 `title`、`source`；需要说明单位、口径或估算方法时填写 `note`。
- 表下注释顺序固定为“注：……”和“资料来源：……”。
- 财务数字右对齐，文字左对齐；同一列保持币种、单位、小数位和正负号一致。
- 表头用名词短语，不在单元格堆叠长段文字；所有表格独占整行，长表格允许在完整行之间分页。
- 不把重要结论只留在颜色中；颜色之外同时保留正负号、文字或风险等级。
- 核心结论使用 3–4 条编辑式编号摘要，风险使用“等级—标题—影响与验证”文字列表；两者都不使用表格线。
- 文末来源索引是工具型表格，可使用浅灰行分隔辅助追踪，但不称为三线表。

## 5. 学术图形规范

- 只有图形能显著提高理解时才生成，通常 1–3 张。
- 使用内联 SVG，禁止外部图表库、3D 图、饼图爆炸效果、双轴误导和装饰性插画。
- 每张图都必须有位于图形下方的连续编号与图题，例如“图 2　营业收入与归母净利润趋势”。
- 每张图填写 `source`；需要解释口径、估算值或基期时填写 `note`。
- 图下注释顺序固定为“注：……”和“资料来源：……”。
- 坐标轴、单位、期间、图例必须完整；不在同一坐标轴混合数量级差异超过 10 倍的系列。
- 使用低饱和深蓝、灰和棕色序列；颜色数量服从信息数量，不额外装饰。

## 6. 报告模式

| 模式 | 核心结构 |
|---|---|
| brief | Header、核心结论、关键指标、驱动与风险、来源 |
| standard | brief + 预期差、业务拆解、盈利质量、资产负债表、指引 |
| deep | standard + 多期趋势、量价拆解、归因、验证清单、完整证据索引 |
| preview | 官方指引、一致预期、关键观察项、Bull/Base/Bear、数据缺口 |
| update | 实际对原预测、预测调整、投资逻辑状态、敏感变量和验证点 |

未适用的章节不生成；适用但缺少数据的章节保留并明确说明缺口。没有实质数据缺口时不生成独立的“数据缺口”章节。风险只保留一个专门章节，顶层结构化风险与正文风险不得重复展示。

## 7. 来源与交付

文末证据索引至少包含材料名称、发布主体、日期、报告期、页码或章节、链接和来源层级。不得只写“某 MCP”；MCP 是获取路径，不是最终证据。

最终 HTML 必须：

1. 分开写入 `research-gate.json` 和不含 `research` 的 `report.json`；
2. 只执行一次 `scripts/build-report.mjs`，由它完成门禁、合并、渲染和 HTML 校验；
3. 自包含，不依赖 CDN、远程字体、远程脚本或远程图片；
4. 带有 `earnings-a4-v1` 模板标记和 Plugin 版本；
5. 通过来源、URL、MCP 字段、勾稽和 HTML 校验；
6. 构建成功后不再打开、搜索、修改、重复渲染或重复校验；
7. 在对话中仅补充 3–6 条核心结论、主要数据缺口和文件链接，不重复完整报告。
