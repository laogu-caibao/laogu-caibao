## 本轮测试中发现并修复的解析问题

| 现象 | 样本 | 修复 |
|---|---|---|
| 报表标题“合并及公司资产负债表”“2026 年半年度合并及公司利润表”识别不到 | 美的 | 标题正则兼容年份前缀、“合并及（母）公司”；取前两列为合并口径 |
| 费用、现金流出用括号列示为负数 | 美的、招行、平安 | 识别括号版式，统一为正数口径 |
| 单位“金额单位为人民币千元”“单位为：千元”“人民币元”单独成行 | 美的、比亚迪、万科 | 单位正则扩展；报表页只认本页单位声明，不继承前文“万元” |
| 无框线表格抽不到行 | 招行 | 增加文本行解析，自动剔除附注编号 |
| “本行股东”“上市公司股东”“母公司所有者”等称谓不同 | 招行、平安 | 科目名统一归一化 |
| 附注列是纯数字（“44”）被当成本期数 | 茅台 | 识别“附注”列并剔除；奇数列兜底 |
| 标题“1、合并资产负债表”“2、合并年初到报告期末利润表” | 宁德、比亚迪 | 兼容编号前缀与“年初到报告期末”；单季度报表不采用 |
| 季报主要数据表含“上年同期 调整前/调整后”列，按位置取数取错 | 中信证券、平安 | 按表头识别“本报告期/年初至报告期末”列 |
| 科目名带嵌套括号“(净亏损以“()”号填列)” | 万科 | 括号说明递归剔除 |
| 巨潮标题“2026年三季度报告”（无“第”） | 宁德 | 报告名改为正则匹配 |
| 东财偶发返回未声明的 gzip | 美的 | 网络层自动解压 |
| 新浪对个别公司利息费用记负数 | 美的 | 天然非负科目取绝对值比对 |
| 金融类“分配股利、利润或偿付利息支付的现金”两接口口径不同 | 招行 | 金融类跳过该科目 |
| 单位识别失败的兜底 | 比亚迪（修复前） | 与接口恰好差 10 的整数次方时按接口量级校正并告警 |

## 场景测试

- **财报当日（接口未更新）**：模拟紫金 2026Q3 两家接口都无数据 → 自动从巨潮取原文，目标期切到 2026-09-30，关键科目状态“原文自洽”（报表与主要会计数据表互相印证），单季营收 892.74 亿由原文“本报告期”补齐。
- **年报深检**：茅台 `--mode deep` → 同时解析 2026 半年报与 2025 年报，审计意见“标准无保留意见”，0 错误。
- **分析层（v0.2）**：`tests/regress.py` 现调用 `analyze.py --recollect`，额外验收：每个指标都带输入值；报告不含荐股用语（买入/卖出/增持/目标价/推荐/看多/看空/上涨空间/抄底/加仓/减仓/止损）。
- **深检分型**（`--mode deep`，写入 `out/<代码>/分型.json`，快检沿用）：紫金 B（行业强周期“有色”，10 年毛利率峰谷差 59%）；茅台 A、美的 A；宁德 C（毛利率峰谷差 56% 但 10 年归母无一年下滑 ≥30%，规则 0.2 判为趋势性变化而非周期——0.1 曾误判为 B）。
- **扫描版原文**：紫金 2025 年报（A+H，352 页）报表页为图片无文字层 → 问题清单注明页码范围，该期以东财+新浪双源为准。
- **历史期冲突**：紫金“在建工程 2016-12-31 东财 vs 新浪”冲突只影响长期均值，headline 不再因此判“结论待人工核对”。
